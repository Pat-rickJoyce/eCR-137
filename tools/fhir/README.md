# FHIR output: developer notes

The app converts and builds FHIR entirely in the browser; it makes no terminology or network calls. The tools here regenerate the checked-in generated files and validate the app's output. tx.fhir.org is used only by `lookup-displays.ps1` and by the HL7 validator.

## Files

| File | Role | Generated by |
|---|---|---|
| `js/fhir/ecr137-cda2fhir.xslt` | eCR-137 conversion rules; imports the upstream transform in `vendor/ecr-transforms` | hand-written |
| `js/fhir/ecr137-fhir-bundle.js` | compiled conversion (SEF) plus the mapping documents it reads | `build-browser-bundle.mjs` |
| `js/fhir/display-table.xml` | verified coding displays | `build-display-table.py` |
| `js/fhir/fhir-rr-builder.js` | FHIR RR from the FHIR eICR, the form and the reportability engine result | hand-written |
| `js/fhir/rr-condition-codes.js` | SNOMED CT reportable condition code per condition pack (RCTC release in `assets/data`) | `build-rr-condition-codes.py` |
| `js/fhir/fhir-annotate.js` | reader layout: entry order, comments, reference displays | hand-written |
| `js/fhir/ig-notes.js` | profile and section text from the eCR 2.1.2 and US Core packages, used in the comments | `build-ig-notes.py` |
| `js/fhir/fhir-json.js` | FHIR XML to JSON | hand-written |
| `js/fhir/fhir-r4-json-types.js` | element names, types and cardinality of FHIR R4, used by `fhir-json.js` | `build-json-typemap.py` |
| `js/fhir/fhir-export.js` | output format (CDA, FHIR, CDA + FHIR) and the dock actions | hand-written |
| `vendor/ecr-transforms/` | `lantanagroup/eCRTransforms` `transforms/cda2fhir-r4` at the commit in `UPSTREAM`, used files only, unmodified | copied |
| `vendor/saxon-js/` | SaxonJS 2.7 runtime and its license | copied |
| `tests/fhir/` | `default-form.json` and one form per condition pack (`forms/`) | `make-condition-forms.py` |

## Regenerate

Run from the repository root.

After changing `js/fhir/ecr137-cda2fhir.xslt`, `js/fhir/display-table.xml` or `vendor/ecr-transforms/`:

```bash
npx xslt3 -xsl:js/fhir/ecr137-cda2fhir.xslt -export:build/ecr137-cda2fhir.sef.json -nogo -relocate:on
node tools/fhir/build-browser-bundle.mjs
```

When new codes appear in the output (display table):

```bash
python3 tools/fhir/collect-codes.py build/fhir > build/codes.json
pwsh tools/fhir/lookup-displays.ps1 -In build/codes.json -Out build/tx-new.json   # merge into tools/fhir/terminology/tx-lookup.json
python3 tools/fhir/build-display-table.py .
```

Display sources: `terminology/tx-lookup.json` (tx.fhir.org `CodeSystem/$lookup`), `terminology/profile-pattern-displays.json` (displays fixed by eCR 2.1.2 and US Core profile patterns), `terminology/manual-displays.json` (displays from the validator's valid-display lists).

After a new RCTC release or new condition packs:

```bash
python3 tools/fhir/build-rr-condition-codes.py
python3 tools/fhir/make-condition-forms.py .
```

From the FHIR packages in the local package cache:

```bash
python3 tools/fhir/build-json-typemap.py ~/.fhir/packages/hl7.fhir.r4.core#4.0.1/package
python3 tools/fhir/build-ig-notes.py ~/.fhir/packages/hl7.fhir.us.ecr#2.1.2/package ~/.fhir/packages/hl7.fhir.us.core#3.1.1/package ~/.fhir/packages/hl7.fhir.us.core#4.0.0/package
```

## Validate

```bash
npm i playwright jszip
python -m http.server 8137 --bind 127.0.0.1          # in another window, from the repository root
# Load Form Data, Format: FHIR, Package ZIP in headless Chromium for the default case, the templates and every condition form
OUT=build/fhir node tools/fhir/generate-fhir.mjs __default__ assets/forms/*.json tests/fhir/forms/*.json
# HL7 FHIR Validator, eCR 2.1.2, terminology on tx.fhir.org, SNOMED CT US Edition
java -jar validator_cli.jar build/fhir -version 4.0.1 -ig hl7.fhir.us.ecr#2.1.2 -sct us -txCache build/txcache -output build/validation.xml -html-output build/validation.html
# zero-tolerance gate: exits 1 on any error, warning or information message not in validation-suppressions.json
python3 tools/fhir/check-validation.py build/validation.xml --unused
```

`validation-suppressions.json` lists every accepted validator message by message id, with the reason it is accepted. `--unused` also lists suppressions that matched nothing, so the list only shrinks; use it on the full set of forms.
